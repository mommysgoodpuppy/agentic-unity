# Example: an agent models and shades a horn

One way to have an agent make art for a VRChat avatar: **everything comes from code, each change
gets rendered and checked automatically, and a person directs by looking at it and saying what's
wrong.** It's not the only way, and Blender is often better for organic shapes. It suits parametric
things, such as a spiral horn, and anything where the behaviour matters as much as the look.

This is real work, reduced only by having avatar-specific comments removed:

- [`horn-glow/`](horn-glow/): a procedural spiral horn with toon, overlay and ray-marched aura shaders,
  plus an FX animator driven by contacts, all generated by one editor script. It checks itself through
  the real avatar build pipeline.
- [`horn-collar/`](horn-collar/): a torn-fabric collar that samples a hat's actual skinned surface, so
  the horn looks as if it punched through it. A smaller and more self-contained example of fitting
  generated geometry to what's already on an avatar.

There are more tools for specific jobs, hardcoded to one avatar, in [`hardcoded/`](hardcoded/README.md).

The originals passed their checks and went into VRChat. **These copies were compile-checked but haven't
been re-run,** so expect small fixes.

## Running them

**HornGlow:** in a throwaway project with the Avatars SDK and VRCFury, copy `horn-glow/HornGlow` to
`Assets/HornGlow`, then:

```sh
mkdir -p /tmp/horn
HORNGLOW_OUT=/tmp/horn Unity -batchmode -force-vulkan -projectPath <proj> \
  -executeMethod HornGlowBuilder.BuildAll -logFile /tmp/horn/unity.log
```

Or use **Tools → HornGlow → Build Prototype**. It writes the mesh, materials, controller, prefab and test
scene, then a report and preview PNGs. In a brand-new project, first create
`Packages/com.vrcfury.temp/package.json` with VRCFury's own content, because VRCFury otherwise makes it 5
seconds after the editor loads, too late for a batch build. Change the code, not the outputs: they get
regenerated.

**Collar:** copy the file into `Assets/VRUnityAgent/Editor`, set `Scene` at the top, and rename "Hat" and
"Horn" for your avatar. With the editor open, write requests to
`Library/VRUnityAgent/HornCollar/request.json`, as described in its header.

## How the loop works

1. **Build a small prototype first.** A separate project with a stand-in avatar (capsule, sphere head)
   builds in seconds, and can't break a real avatar. Copy the results in once they work, `.meta` files
   included, so GUIDs match and rebuilds can update them in place.
2. **Express the shape as parameters.** "Thicker toward the base" is then a one-line change, plus a re-render.
3. **Let the agent look at it.** `closeup` renders any part from any yaw and pitch. Keep the camera fixed
   between runs, or before and after can't be compared. **Debug materials showing normals or tangents**
   caught more than beauty renders.
4. **Build self-checks into the generator:** counts, bindings, measured seam angles, an animator simulation.
   The report grew to 35 checks, each added after a real problem, so a fix can't quietly regress.
5. **The person looks, and describes or sketches what's wrong.** A rough sketch of the groove's profile
   settled what paragraphs hadn't. Then the agent finds the cause. Report what's *not* verified,
   especially anything that needs a headset.

## Modeling lessons

- **`Vector3.normalized` returns zero below 1e-5.** Finite-difference normals on a tiny mesh are about
  1e-8 long, so every normal silently fell back to "up" and the horn shaded flat. The toon shader hid
  this for several renders. Normalize by hand.
- **Geometry makes the highlights.** The original horn's look came from 10-sided low-poly faces with
  smoothed normals, which no texture trick reproduced. Copying its UV unwrap only added glitches. Inspect
  the actual topology of what you're matching.
- **Let the topology follow the feature.** Mesh rows follow the spiral so the groove's bottom sits on
  edges, and it stays sharp because normals are never blended across it.
- **A matcap shows every normal error.** A seam kept reappearing after two wrong fixes. The cause: band
  numbers counting turns differed by one across the UV seam, making a hard crease along the horn. The
  report now measures the normal difference at every seam pair, so "fixed" is a number.
- **Slivers near a tip average into broken normals.** Fade the feature out before the tip, end on a plain
  ring, and cap it with ordinary rings using analytic normals. Set tangents analytically as well.
- **Reuse an existing material without its seams.** Point UV0 at one spot where the base material is flat,
  and keep the mesh's own coordinates in UV1 for the overlay shader.
- **Check your tools' starting state.** A confident finding about the old horn's UVs turned out to be
  measuring Blender's default cube. Use `--factory-startup` and start from an empty scene.
- **Fit to what's there.** The collar samples the hat's real skinned surface at build time and works in the
  horn's local space, rather than taking offsets from eyeballing.

## Shader lessons

- **Single-pass stereo is easy to miss, and looks fine on desktop.** A fragment shader that reads
  `_WorldSpaceCameraPos` or `UNITY_MATRIX_V` needs `UNITY_SETUP_STEREO_EYE_INDEX_POST_VERTEX`, or both eyes
  use the left eye's camera. If it uses object matrices in the fragment, it needs the instance ID passed
  through as well.
- **Check variants you can't see.** The builder compiles every pass for D3D11 with no keywords,
  `INSTANCING_ON`, `UNITY_SINGLE_PASS_STEREO` and `STEREO_INSTANCING_ON`. It also renders a 64 mm stereo
  pair, a mirror-like view, and from inside the volume. None of those is a headset, though.
- **Volumes:** the aura ray-marches inside a box mesh, with `Cull Front` so it still draws with the camera
  inside. Widen the box when you change the shape, and budget the steps (here up to 64 + 24 + 40 per
  pixel: fine on PC, not on Quest).
- **Editor globals aren't VRChat's.** `_VRChatCameraMode` was −1 in one project because another package set
  it, so a test for exactly 0 hid the effect. Use a range (below 0.5), and skip mirrors with
  `_VRChatMirrorMode`.
- **First-person effects:** VRChat shrinks head children in first person. Test against distance in world
  space, not inside a box in object space. Use `VRCHeadChop` to keep the object full size, and switch it on
  with an `IsLocal` animator layer so remote players don't render it.
- **Headsets render well past what the lenses show.** An edge haze that looked right on a desktop preview
  was nearly invisible in VR. Pull it in further than seems necessary, and test in a headset.

## Animator lessons

- **Simulate it.** A PlayableGraph, manually evaluated, with parameter drivers applied through
  `VRC_AvatarParameterDriver.OnApplySettings` as Gesture Manager does, can run scripted timelines headless.
  Note that the simulation can't prove contacts collide in VRChat.
- **Test at low frame rates.** Each empty animator state costs a whole frame, so a step through two of them
  ran about 30% slower at 8 fps, and users reported the horn being harder to trigger. Hold timers inside
  states that re-enter on exit time.
- **A state with no motion behaves like a 1 s clip for exit time.** Leave it by condition.
- **Check names after the build.** VRCFury renames parameters and folds layers into a Direct blend tree, so
  look in the built controller, and search blend trees too.
- **Sync sparingly.** Synced floats cost 8 of 256 bits, and a real avatar may have few left. Anything
  every client can compute from contacts doesn't need syncing.
- **Blending colours exactly:** a hue function that's piecewise linear between multiples of 1/6 is
  reproduced exactly by blending 7 clips.
- **Timing is a design question.** "It's stuck off" turned out to be that slow strokes let the charge drain,
  and possibly that the emulator wasn't enabled. Adding the slow case to the simulation kept it fixed. Enable
  Gesture Manager before concluding that something is broken.

## Going from prototype to avatar

The horn itself is generic, but a few things depend on your avatar: `TiltDegrees`, sizes, and the base
material. `attach-prefab` places it by aligning to an existing horn's base and axis; `edit` hides the old
horn without deleting it. The eye glow needs a copy of your face material with lilToon's second emission
on, through an iris mask you make from your own face texture. That setup, and the mask, aren't included
since they come from a paid avatar's assets.

The `TouchSocket` receiver and test socket use VRCFury SPS tags. If you don't want that, delete them along
with the `Socket` parameters, or use the hand contacts alone.
